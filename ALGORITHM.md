# Map generation and coordinate rules (v5)

## Coordinates and geometry

- X points right, Y points up, and Z points forward. Runtime distances are integer millimetres; the editor displays metres. FBX file units are converted using `UnitScaleFactor`; the Unity prefab root and scene transform use scale 1.
- Each module stores `minX/maxX/minY/maxY/minZ/maxZ` relative to its model origin. FBX import supplies the initial axis-aligned box. A manual advanced override changes the box used for generation; the editor does not test the actual mesh for collision.
- A port stores `edge` (`N/E/S/W` = `+Z/+X/-Z/-X`, the opening's outward direction), `doorTypeId`, local `(x,y,z)`, and `allowedTypeIds`. Its rectangular opening has the `width` and `height` of its door type in `doorTypes`. Door type sizes are unique: any two differ by more than 20 mm in width or height. The port centre must lie on a vertical side face: on its plane and within its horizontal and vertical extent. A module may reserve space above its box (`reservedAbove`: 0, millimetres, or null = open to the sky); its side faces then extend up through that space, so a door centre may sit above the box top (e.g. a rooftop slab whose door rises above its low parapet). The opening rectangle may overhang the face's edges, top or bottom; joining only uses the centres, so an overhanging opening is legal, and Unity is responsible for building or sealing any part of it beyond the box.
- A port with `allowedTypeIds: null` accepts any type permitted by the directed relation graph; an array restricts the accepted types. Both ports must accept the opposite type.
- A placement has world `(x,y,z)` and a rotation of 0, 1, 2, or 3 quarter turns about +Y. X/Z transforms are `(x,z)`, `(z,-x)`, `(-x,-z)`, `(-z,x)`; local Y is unchanged. The new module's world translation is the existing port's world center minus the rotated new port's local center, including Y.
- Bounds rotate around the model origin, then translate. For overlap tests a module occupies its bounds plus any space it reserves above (to infinity when open to the sky), so nothing is placed in that space. Two boxes overlap only when their intersections have positive length on **all three axes**. Face, edge, or point contact is legal. This simple box may reject otherwise usable empty space under a stair or near decoration.

## Quotas and search

1. `modulesAfterStart` counts non-start modules. The map contains one additional start module, sampled uniformly from the start type's concrete modules and placed at world `(0,0,0)` with rotation 0. The start type has no share and cannot be the target of a directed relation.
2. Non-start percentages sum to 100%. Multiply each by `modulesAfterStart`, take the integer floors, then distribute remaining slots by descending fractional remainder and ascending type ID. `requiredMin` is included in these targets and cannot exceed its target.
3. Concrete modules are sampled with replacement, uniformly within each type, into a quota bag. A placed module can extend from any unused port. A directed `from → to` relation, the same `doorTypeId` on both ports, both ports' type permissions, opposite rotated side normals, exact three-dimensional center alignment, and no positive-volume overlap are required. Each new module attaches to one parent; the search does not create cycles.
4. Candidate rank is `-ln(max(U, 1/2^32)) / (connectionWeight × remainingConcreteModuleCount × preference)`. Try ranks ascending, then parent index, module ID, port ID, rotation. Weights affect adjacency preference and do not change type quotas. `preference` comes from the child type's soft placement preferences: `2^((preferFar/50) × steps + (preferHigh/50) × floorY / 3000)`, where `steps` is the candidate's step count from the start (parent steps + 1) and `floorY` its world base height in millimetres, so 100 % means 4× per step or per 3 m and negative values favour near or low. At each search step these factors are divided by their mean over that type's candidates, so a preference shifts *where* a type is placed without changing how strongly it competes with other types. With both preferences at 0 the ranks equal the earlier formula. Uniform random draws are taken in candidate order, so results stay reproducible.
5. Depth-first search backtracks on failure. Each level tries at most 96 ranked candidates. The search budget follows the **search time limit** set in the file menu (default 30 s, 5–600 s, saved per browser): it checks at most 12,000 candidates and restarts the sampled bag at most max(24, 2.4) times per second of the limit (so 10 s gives 120,000 checks and 24 restarts), and the browser stops the worker when the limit is reached. A full result stops the search. Otherwise select the best partial result by required minimum deficits, total count deficit, then absolute type-target deviation, and show warnings.

## Randomness and preview

The generator uses unsigned 32-bit `xorshift32`: `x ^= x << 13; x ^= x >>> 17; x ^= x << 5`. A zero seed is replaced with `0x6d2b79f5`; each random fraction is the next unsigned result divided by `2^32`. Stable candidate enumeration and millimetre coordinates make completed layouts reproducible for a fixed seed.

The preview draws colored occupancy boxes and rectangular ports. One connected rectangle is drawn for each joined pair with a solid empty outline. Unused ports have a solid hatched outline and are normal; Unity is responsible for sealing them. The connection state is preview-only and is not exported as a rule. Preview camera orbit, pan, zoom, and focus do not change any runtime data.
